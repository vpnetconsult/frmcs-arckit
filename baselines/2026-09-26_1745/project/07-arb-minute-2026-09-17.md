## Resolution 1 — Q-17: what a detected security event obliges on a recovery path

| | Option | Disposition |
|---|---|---|
| **0** | **Do nothing** — the gate is the operator's procedure; ADR-012 is a conformance decision and should not reach into operating rules; Q-17 closes rejected, finding retained in the incident annex | **Rejected.** The annex records the fact; it does not create an obligation. A register whose founding incident contained an unbounded security gate on the recovery path, and whose conformance ADR extends detection to security events without saying what detection obliges, has the gap Q-17 names. Declining to require *anything* leaves the next such gate as unbounded as the last |
| **1** | **Full adoption into Decision item 5** — item 5 gains both the time-box + named-authority rule and the SuppEssFunc enumeration, as the queue entry proposed | **Rejected.** It puts an operating-procedure rule inside a conformance decision, which is the mis-homing Q-17 itself flagged as its own weakest point. Item 5 is about *detection*; who may proceed on a recovery path is an *SMS* matter (item 4) |
| **2** | **Enumeration only** — item 5 gains the SuppEssFunc enumeration duty; the time-box / named-authority rule is not adopted anywhere, left to the operator's SMS with no register requirement | **Rejected.** Enumerating an adverse effect without requiring that it be bounded is a list, not a control. DB's rule was presumably already enumerated somewhere; what it lacked was a bound and a person |
| **3** | **Split — item 5 gains the ENUMERATION duty, item 4 gains the BOUND** | **✅ CARRIED** |

**Carried (Option 3).** ⚠️ **The board decides the OBLIGATION and declines to invent the INSTRUMENT** — the ARB-2026-09-06 R1 principle, applied again. What is decided:

- **Decision item 5 gains the enumeration duty:** every security obligation that stands on a safety-relevant recovery path — between a detected event and an authorised recovery action — is **listed as an adverse effect on essential functions, with its mitigation, in the form of `SP-SEC-SuppEssFunc`** (E-2026-09-05-13). The instrument is the sector's own; this session names it in the ADR for the first time.
- **Decision item 4 gains the bound:** the operator's SMS states, for each such procedure, **a time box and the named authority who may proceed without completing it**. The register requires that a bound exist and be owned; **it does not set the number** — that is the operator's risk decision under CSM-RA, and a register with no operational data has no basis to set it.
- **What is expressly NOT decided:** that the gate should be removed, shortened, or bypassed. Failing over during an actual compromise can propagate it (the queue entry's own caution). The board's position is that an *unbounded* gate on a safety-relevant recovery path is indefensible, and that a bounded one is the operator's to set.
- **Consequence for the 23-June record:** `incident-annex.md`'s corrected characterisation (2026-09-15) stands as the worked instance; ADR-007 item 3's sixth injection class (the procedural gate) is the test that the bound is exercised, not merely written.

## Resolution 2 — Q-18: model provenance evidence in the procurement gate

| | Option | Disposition |
|---|---|---|
| **0** | **Do nothing** — one slide from an operator, no format standard on file, and ADR-002 rule 2a already covers training lawfulness for generative components; Q-18 closes rejected | **Rejected.** Rule 2a covers *lawfulness* of training for *generative* components under GDPR. It does not cover provenance, licence, evaluation record or update mechanism, and it does not reach non-generative learned components or FRMCS PDEs that ship a model. The gap is real and the source count is not the point — the gate's own logic (SBOM for software) implies it |
| **1** | **Adopt "AI BOM" by name** into item 1 and block A for (a) and (b), as the queue entry proposed | **Rejected.** It names an artefact whose standard format the register does not hold (no CycloneDX/SPDX ML profile on file). A bid condition naming a format nobody can uniformly produce is the size-filter failure minuted at ARB-2026-09-06 R4, repeated |
| **2** | **Home it in ADR-002 rule 2 only** as a sixth condition; ADR-012's gate gains a pointer | **Rejected as incomplete.** It covers the oversight layer's own learned components and nothing else. An FRMCS product with digital elements that ships a model — a cab radio with a learned RF-optimisation function, a core with an embedded analytics model — is in ADR-012's scope and outside ADR-002's. The gate must reach both |
| **3** | **Obligation without format — "model provenance evidence" in ADR-012 for (a) and (b), fields named, format expressly unspecified; ADR-002 rule 2 gains it as a sixth condition by cross-reference** | **✅ CARRIED** |

**Carried (Option 3).** What is decided:

- **Decision item 1 and action item 2 block A gain "model provenance evidence"** as bid evidence, alongside the SBOM, for **(a)** any learned component of the agentic-oversight layer and **(b)** any FRMCS PDE that ships a trained model. **Fields:** model identity and version · training-data provenance and licence · evaluation record against the declared ODD (ADR-010 item 5) · weight-update mechanism and window (the block-B update-capability question, asked of the model) · CVD contact for model vulnerabilities. **Format expressly unspecified** — the register does not hold a standard; when one is on file, adopting it is an implementation item, not a decision.
- **ADR-002 rule 2 gains a sixth condition by cross-reference** — a class-1/2 learned component goes live only with the ADR-012 model provenance evidence on record — so the two records cannot diverge. Rule 2a's lawfulness assessment is unchanged and distinct.
- ⚠️ **Size-filter consequence minuted, not discovered later:** a provenance-and-evaluation requirement on models is a further filter against small suppliers and small operators (E-2026-08-19-13, r = .42). The board accepts it on the same ground as ARB-2026-09-06 R4 — a gate that cannot see what a model was trained on cannot govern it — and records that the *supported variant* obligation (ADR-013 constraint 3) applies here too.
- **The ceiling applies:** like every clause in this gate, this is a requirement to build to and to evidence; it discharges no conformance.
